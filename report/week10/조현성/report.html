01

기존 xv6 — Round Robin

스케줄러는 priority를 보지 않는다. RUNNABLE을 발견 순서대로 1틱씩 돌릴 뿐.

핵심 동작

  • RR공평하지만 멍청하다. 셸의 키 입력도 CPU 무한루프와 동등하게 큐 끝에 줄 선다.
  • ∅분류 신호 없음. RR 루프 안에 IO/CPU bound를 가릴 입력 자체가 없다.
  • 1고정 quantum = 1 tick. 매 틱 yield → 컨텍스트 스위치 최다.
  • ✓완전 재현 가능. 단점이 아니라 강점 — LLM이 들어와도 깨면 안 되는 성질.
// kernel/proc.c — scheduler() for(;;){ // 테이블 순회, priority 미참조 if(p->state == RUNNABLE){ p->state = RUNNING; swtch(...); // 발견 순서대로 } }
02

현대 OS — Windows · macOS

다단계 우선순위 큐 + 행동 관찰 기반 부스트/감쇠. 셸이 깨면 즉시 위로 끌어올려 선점한다.

강점과 한계

  • ↑즉시 선점. 셸이 깨면 부스트되어 CPU 루프를 선점 → 응답 지연 거의 0.
  • ~적응형 quantum. Windows FG/BG, macOS QoS로 슬라이스 차등.
  • ⏱행동을 본 *후* 분류. sleep/wake가 쌓여야 판단 — 갓 fork된 make는 행동 누적 전까지 오분류 구간.
  • ⚙수동 구성·튜닝. Job Objects/cgroups, sysctl 기본값은 워크로드 무관한 평균값. 운영자가 손으로.
  • ×cross-instance 학습 없음. 데이터는 풍부히 수집하지만, 다음 make 인스턴스에 자동 반영 안 됨.
03

LLM 어드바이저 모델 — 이 프로젝트

커널 RR 루프는 한 줄도 안 바뀐다. 사용자공간 사이드카가 procstat을 보고 분류한 값만 흘려보낸다.

클래스 → 기본 quantum (커널의 *유일한* 정책)

클래스quantum의도
INTERACTIVE 1latency 우선
IO_BOUND 1sleep 빈번
NORMAL 1원본 xv6 동등
CPU_BOUND 4스위치 비용 ↓
BATCH 8throughput 우선
SYSTEM 2짧되 여유

현대 OS가 못 보던 두 차원

  • ①의미적 prior. name="make" → 행동 관찰 *전*에 BATCH 분류. 현대 OS의 오분류 윈도우를 제거.
  • ②cross-instance 학습. ZOMBIE 직전 lifetime 스냅샷 누적 → 다음 동명 인스턴스에 첫 분류부터 적용.
  • ⌽큰 quantum. CPU_BOUND는 quantum 4 → 컨텍스트 스위치 1/4, throughput ↑.
  • ⤳트리 묶음 정책. sh→make→cc 트리 전체를 "빌드 트리"로 일괄 강등.

설계 4원칙 — fast path와 결정성을 깨지 않는 격리

PRINCIPLE 01
Bypass 동등
advisord 미실행 + 디폴트(NORMAL·q1) → 원본 xv6와 비트 단위 동일.
PRINCIPLE 02
결정성 회복
syscall은 단순 setter. 결정적 분류기면 전체 결정적.
PRINCIPLE 03
Fail-static
advisor가 죽어도 마지막 class/quantum/prio로 계속 동작.
PRINCIPLE 04
Observable
^P · advstat · getprocstat_all 모두 advisor와 동일 데이터.
04

정면 비교

같은 문제를 세 방식이 어떻게 푸는가. 초록 = LLM 어드바이저가 추가하는 차원.

문제기존 xv6현대 OS (Win·mac)LLM 어드바이저
스케줄러 선택 발견 순서 RR · priority 미사용 다단계 큐 + FG/IO 부스트 이름·의도 prior를 관찰 *전* 사용
fork 시 자식 분류 부모 priority 정적 상속 상속 후 행동 관찰로 적응 (오분류 윈도우) exec된 name으로 첫 syscall 전 분류

종료 프로세스 통계 kwait 회수 시 휘발 ETW·/proc로 풍부히 *수집* 이름별 prior로 학습·재사용

fork 폭주 방어 NPROC 한도 도달까지 무방어 rlimit·pids.max (양적 한도) 이름·트리 모양 기반 사전 의미 구분
panic 사후 분석 짧은 문자열 + 레지스터 덤프 BSOD·kdump (운영자 숙련 요구) 시계열 + 자연어 진단 (제안만)

핵심 패턴 — 현대 OS는 행동 관찰(sleep/wake·vruntime)이거나 수동 구성(job·cgroup·sysctl). LLM 어드바이저는 그 앞단에서 의미적 prior와 cross-instance 학습을 보강한다 — 대체가 아니라 보강이다.
